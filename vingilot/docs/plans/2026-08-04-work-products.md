# Work Products — What a Run Changed, Visible

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A delegated Run's *work product* becomes a first-class artifact: after the command exits, the executor captures the worktree's changes (status, bounded diff), commits them on the run branch, and records everything as typed evidence; the desktop RunDetail renders the diff with real +/- coloring. Then the loop is proven with a **real headless agent** (`claude -p`, cheapest model, one tiny objective) making an actual change that shows up as a reviewable diff in the UI.

**Architecture:** Two new evidence kinds (`diff`, `commit`) via migration 0003. The executor grows a post-command capture step (fenced, like everything else): `git status --porcelain` → if dirty, `git add -A && git commit` **inside the run's own worktree on the run's own branch** (this is the one place `add -A` is correct: the worktree exists solely for this Run, and the commit IS the artifact), then bounded `git diff HEAD~1` evidence. Desktop island gets a pure diff render-model + a Diff section in RunDetail. The agent-harness integration is configuration, not code: `VINGILOT_CMD` already runs anything; the plan wires the documented example and proves it live once.

**Tech Stack:** unchanged (Rust executor/coordinator, island React + node --test).

## Global Constraints

- Branch **`vingilot/work-products`** from `vingilot/executor-v1`. Trailers per ADR-004; `git commit -F`; never amend other sessions' commits; never `git add -A` **in the vingilot repo itself** (the run-worktree capture commit is the sole, documented exception — it operates on a Run's task worktree, never on this checkout).
- Code only under `vingilot/` + `desktop/src/features/runs/**`. check-seams exit 0 pre-commit. Gates: `coordinator-check.sh` (with `COORD_DATABASE_URL=postgres://buzz:buzz_dev@localhost:5435/vingilot_coordinator`), desktop `pnpm check && pnpm typecheck && pnpm test` when island files change.
- No unsafe; no new unwrap/expect outside cfg(test). Long commands via Bash run_in_background + poll.
- **Budget discipline for the live agent proof (Task 4):** exactly ONE `claude -p` invocation in the whole plan, `--model haiku`, a one-file objective, `--max-turns 4` cap. E2e TESTS never call claude — they use `sh` stubs. If the claude CLI is unauthenticated or fails, fall back to the sh-based diff demo, say so honestly, and the plan still completes (the diff pipeline is the deliverable; claude is the garnish).
- Evidence honesty: truncated diffs carry an explicit truncation marker with the untruncated byte count; a capture failure is evidence + a note, never silently skipped.


### Executor capture step (after the command exits, before the outcome transition)

```
fence(...)                                     # per-op, as everywhere
git -C <wt> status --porcelain                 # evidence kind=note: "workdir status:\n<...>" or "workdir clean"
if dirty:
  git -C <wt> add -A                           # the Run's own worktree — the documented exception
  git -C <wt> -c user.name="Vingilot Executor" -c user.email="executor@vingilot.local" \
      commit -m "run <id8>: <objective, first 72 chars>"
  evidence kind=commit: "<sha> run <id8>: <objective>"
  git -C <wt> diff HEAD~1 --stat               # evidence kind=note (the stat)
  git -C <wt> diff HEAD~1                      # evidence kind=diff, capped 192 KiB with truncation marker
outcome transition + note (unchanged)
```

Capture failures (e.g. git errors) → evidence kind=error + note "outcome: completed (capture failed)" — the RUN outcome still reflects the command's exit code; capture is reporting, not verification.

**Amendment (post-Task-2, 2026-08-04):** the diff evidence cap actually implemented is **48 KiB**, not the 192 KiB cited above. The coordinator's per-row evidence cap (`evidence::MAX_CONTENT_BYTES` in `vingilot/coordinator/coordinator/src/evidence.rs`) is a fixed 64 KiB and predates this task; 192 KiB of diff plus a truncation marker cannot fit in one evidence row under that ceiling, and splitting a single diff across rows is out of scope here. `MAX_DIFF_EVIDENCE_BYTES` in `vingilot/coordinator/executor/src/lib.rs` is set to 48 KiB — comfortably under the 64 KiB row cap with headroom for the truncation marker — and the truncation marker always names the real, untruncated byte count (evidence honesty is unaffected; only the cut point differs from this plan's original prose). This note reconciles the plan text with the shipped behavior; the 192 KiB figure above is historical and superseded by this amendment.

### Island

```ts
// runModel.ts additions
export type DiffLineKind = "add" | "del" | "hunk" | "meta" | "ctx";
export const diffView: (raw: string) => { lines: {kind: DiffLineKind, text: string}[]; truncated: boolean };
// classification by prefix: +++/--- → meta, @@ → hunk, + → add, - → del, else ctx; detects the executor's truncation marker.
```

`RunDetail`: a **Diff** section rendering `kind=diff` evidence through `diffView` — mono, `add` in the ok color, `del` in the stop color, `hunk` muted bold; `kind=commit` rows shown in the Evidence timeline with a `⎘` prefix. Colors via existing island conventions (stock Tailwind), `data-testid="run-diff"`.
