### Findings (read-only recon, 2026-08-13)

**Mic ownership is native, huddle-owned, not the webview alone.**
`HuddleContext.tsx`'s `connectAndSetupMedia` calls `navigator.mediaDevices.getUserMedia` directly
in the webview (a real browser API — Rust does no mic capture of its own), but it is only
reachable from `startHuddle`/`joinHuddle` *after* `invoke("start_huddle"/"join_huddle")` has
already created an ephemeral relay channel. The `MediaStreamTrack` feeds `setupAudioWorklet()`
(`huddle/lib/audioWorklet.ts`), which batches 100ms @ 48kHz f32 PCM and does a raw binary
`invokeRawBinary("push_audio_pcm", bytes)` per batch.

**The Rust side is hard-wired to `HuddleState`, not a standalone service.** `push_audio_pcm`
(`huddle/mod.rs`) reads `state.huddle()?.stt_pipeline` — with no active huddle, bytes are
silently dropped. `start_stt_pipeline` requires `hs.ephemeral_channel_id` and errors otherwise.
There is no non-huddle STT slot in `AppState` before this task.

**There are no partial transcripts — the plan's original assumption above (Task 3's old wording)
was wrong.** The STT engine (`huddle/stt.rs`) is `sherpa_onnx::OfflineRecognizer`
(non-streaming): raw PCM → rubato resample 48k→16k → earshot VAD groups voiced frames → on
~300ms silence (`SILENCE_FLUSH_FRAMES`) the whole buffered utterance is decoded **once**, sending
one **final string** per utterance over a `tokio::mpsc::Receiver<String>`. That receiver is
consumed only by `spawn_transcription_task`, which signs and posts a **kind:9 relay message** to
the huddle's ephemeral channel. **No Tauri event is ever emitted to the frontend with transcript
text** in the huddle path — the webview only sees huddle transcripts by subscribing to the
ephemeral channel like any other chat message. That shape (a relay post, readable by every huddle
member) is categorically wrong for "text into a local draft" and would leak draft text to other
participants — dictation needed its own delivery path (a Tauri event), not huddle's.

**Model download**: `download_voice_models` fires two independent background downloads — STT
(NVIDIA Parakeet TDT-CTC 110M, English-only, SHA-256-pinned, ~100MB, installed to
`~/.buzz/models/parakeet-tdt-ctc-110m-en/`) and TTS (Pocket). **No multilingual or Turkish sherpa
model ships or is referenced anywhere in this codebase** — one hardcoded English archive, one
hardcoded URL. `VoiceSettingsCard`/`voiceSettingsLogic.ts` are TTS speaker-*voice* pickers only
(Pocket TTS voice pack: anna/vera/mary) — there is no STT-language selector to expose, so the
plan's original Task 3 line assuming one exists was wrong too.

**VAD/endpointing is real and already segments speech** (earshot VAD +
`SILENCE_FLUSH_FRAMES`≈300ms / `MIN_VOICED_FRAMES`≈192ms in `huddle/stt.rs`), but it is not
surfaced anywhere as an event — its only observable effect is "a finished utterance produces one
flushed string." There is no VAD-idle signal exposed to the frontend for a session-level
auto-stop timer; the honest move (used by Task 3) is timing the auto-stop from *time since the
last transcript event* rather than inventing a parallel raw-audio silence detector.

**Composer surfaces**: DM/channel/team-thread all share `MessageComposer.tsx`, whose content is a
rich-text abstraction (Tiptap), not a plain string — the fold must go through the rich-text
insertion API, not raw string concatenation. The workspace's Ask box
(`runs/lib/askMode.ts` + `usePalette.ts` + `CommandPalette.tsx`) is a different, plain-string
surface entirely — two distinct fold targets, not one shared draft primitive.

**E2E fakability**: the mock bridge had no cases at all for `push_audio_pcm`,
`start_stt_pipeline`, `speak_agent_message` before this task — only `get_model_status` and
`voice_input_mode`. `huddle-transcription.spec.ts` fakes `getUserMedia` at the page level with a
silent oscillator and never drives a transcript through Rust (mock IPC intercepts the whole
layer). Dictation is spec-testable the same way: a same-shaped fake-mic init script plus new mock
cases for the new dictation commands and the existing generic
`__BUZZ_E2E_EMIT_TAURI_EVENT__` helper to simulate the transcript event — no mic, no real sherpa
binary, ever exercised by a spec.

**Recommendation that Task 3 followed:** neither "reuse the huddle pipeline as-is" nor a pure
"second `getUserMedia` wiring" was sufficient. Dictation needed a **third, small Rust surface**:
`huddle::stt::SttPipeline` reused verbatim (it already takes `model_dir` + atomics, no huddle
types), instantiated from a **new, huddle-independent slot** (a process-global static, not an
`AppState` field — see the Build section) with **new commands**
(`start_dictation`/`stop_dictation`/`push_dictation_audio_pcm`) whose text sink is a Tauri
**event** (`dictation-transcript`), never a relay POST.

## Build — what actually landed (Task 3, 2026-08-14)

### Design decisions

- **A third Rust surface, not huddle reuse or a second `getUserMedia` wiring** (Task 1's
  recommendation, followed exactly): `desktop/src-tauri/src/dictation.rs` reuses
  `huddle::stt::SttPipeline` verbatim (unmodified) but owns it from a **process-global
  singleton** — `static DICTATION_STATE: Mutex<DictationState>` — rather than a new `AppState`
  field. That mirrors `huddle::models`' own `GLOBAL_MODEL_MANAGER` pattern already in this
  codebase and, unlike an `AppState` field, costs `app_state.rs` (already at the file-size
  ratchet's ceiling) not one line.
- **Three new commands**, registered in `vingilot_command_table.rs`:
  `start_dictation` (idempotent; returns `Err("STT model not ready")` — the same sentinel
  `huddle::start_stt_pipeline` uses — when the model isn't downloaded), `stop_dictation`
  (always safe, no-op when idle), `push_dictation_audio_pcm` (same raw-PCM wire shape as
  huddle's `push_audio_pcm`, reading the dictation slot instead).
- **A Tauri event, never a relay POST.** `start_dictation` forwards every string off the
  pipeline's `text_rx` as a `"dictation-transcript"` event via `app.emit`. This is the one
  piece of new plumbing Task 1 said was missing — huddle's only text sink
  (`spawn_transcription_task`) posts a kind:9 relay message, which would leak a draft to every
  other huddle member.
- **Fold model: append-only, no partial.** `dictationFold.ts`'s `foldDictationSegment` /
  `dictationInsertionText` are pure functions; the composer inserts only the *delta* at the
  rich-text cursor (never a wholesale `setContent`, which would risk mangling mention/emoji
  atoms), the Ask box appends to its plain `query` string directly.
- **Idle auto-stop rides the real VAD signal.** `useDictation.ts` resets an idle clock on every
  `dictation-transcript` event (or on `start()`) and auto-stops after 20s with no new one —
  timed from evidence of real speech activity, not a parallel raw-audio timer (Task 1's finding
  that no VAD-idle signal is exposed to the frontend).
- **Auto-stop on send is synchronous, not `isSending`-reactive.** The composer calls
  `dictation.stop()` at the top of `submitMessage`, before any `await`. An earlier draft watched
  the `isSending` prop instead; the Playwright RED-proof below caught that a fast (or mocked)
  send can flip `isSending` true→false within one React batch, never actually observed by an
  effect — a real bug, not just a test artifact, since production sends can be just as fast.
- **Model download offer, not `VoiceSettingsCard`'s literal copy.** Task 1 found
  `VoiceSettingsCard` has no STT-download UI at all (it's a TTS voice *picker*); "the existing
  `download_voice_models` flow" the requirements pointed at doesn't have reusable copy to lift.
  `useDictation.ts` calls the same `download_voice_models` command HuddleBar's model-status poll
  already uses, shows a "downloading speech model…" status row, and retries `start_dictation`
  once ready — never a silent failure, honestly reusing the *mechanism* rather than copy that
  doesn't exist.
- **English-only v1, no language picker.** Task 1 confirmed no multilingual/Turkish sherpa model
  ships and no STT-language selector exists to expose — inventing one would be describing a
  choice the model manager cannot honor.

### Chord: ⌃⌘D, composer-only

Five-claimant audit (`dictationKeys.ts`'s header has the full trail, in
`scratchMarkdownKeys.ts`'s style): muda's vendored predefined-menu source (0.19.3,
`items/predefined.rs`) has no `⌘D` of any kind — its only Control chord is `⌃⌘F` (Fullscreen);
`useAppShellKeyboardShortcuts.ts` claims `⌘F`/`⌘K`/`⇧⌘K/N/O/A` and reads no `ctrlKey`; the other
global hooks (`⌘,`, `⌘±/⌘0`, `⌘R`, `⌘[`/`⌘]`/`⌃⌘←→`, Escape) claim no `⌘D`; this island's own
maps (`terminalKeys.ts`, `paletteKeys.ts`, `columnKeys.ts`, `paneKeys.ts`,
`scratchMarkdownKeys.ts`, `searchKeys.ts`) claim none either — `terminalKeys.ts` explicitly
leaves plain `⌘D`/`⇧⌘D` unbound for iTerm's split, which is a different chord entirely. AppKit's
⌥-synthesis rule (the reason `scratchMarkdownKeys.ts` avoids `⌥⌘M`) doesn't apply here: `⌃⌘D`
touches no Option modifier, and macOS's own Dictation shortcut is "press Control twice," not a
modified letter.

`⌃⌘D` is bound **only in the composer** (`useComposerDictation.ts`), scoped to the composer
having focus — a `window`-level listener with no scope check would fire for every mounted
composer (e.g. a thread panel beside the main one) on one keypress. **The Ask box is
button-only, deliberately**: it already claims most of the keyboard in a capture-phase `window`
listener while open (`CommandPalette.tsx`'s own header), and a second global chord contending
for the same keys inside a modal was judged a worse trade than one click.

### Known deviation: the file-size ratchet on `MessageComposer.tsx`

`MessageComposer.tsx` was already at 1014 lines (over the desktop ratchet's 1000-line cap,
grandfathered by "may not grow further") before this task touched it. Composer wiring was
extracted as far as reasonably possible into `useComposerDictation.ts` (fold callback, ⌃⌘D +
Esc handling, nav-away auto-stop — none of that lives in `MessageComposer.tsx`), and the status
row was moved into `MessageComposerToolbar.tsx` (which has headroom) rather than rendered
directly. What remains in `MessageComposer.tsx` — one hook call, one `dictation.stop()` at the
top of `submitMessage`, one dependency-array entry, one `dictation={dictation}` prop — is +14
lines net. An `isSending`-watching version got this to +9, but the RED-proof (below) showed that
design was unreliable under a fast/mocked send, so correctness won over the ratchet. **This is a
disclosed exception, not a silent one**: a genuine fix is splitting `MessageComposer.tsx` itself
(the same move `vingilot_command_table.rs` made for `lib.rs` at its own ratchet ceiling), which
is real work sized separately from a dictation feature and is not done here.
