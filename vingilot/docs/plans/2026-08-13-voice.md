# Voice — the crew speaks, and the Captain dictates

> **For agentic workers:** implement task-by-task. Steps use checkbox (`- [ ]`) syntax.
> **Owner's ask, verbatim:** *"TTS lazım. konuşarak yazdırma."*
> **Queue position:** after the crew-usable fixes land (v0.2.2).

**The stack already exists — this plan is wiring, not engineering.** Upstream ships a complete
local voice pipeline for huddles: `crates/buzz-voice` (sherpa-onnx 1.12 — the same engine whose
CI download flaked yesterday), and the desktop already registers `download_voice_models`,
`start_stt_pipeline`, `set_voice_input_mode`, `set_tts_enabled`, `speak_agent_message`,
`push_audio_pcm`, with UI in `VoiceSettingsCard`, `HuddleBar`, `useTtsSubscription`. All of it
is gated inside the huddle feature. The work is to open two of those doors outside a huddle —
**everything stays local**: sherpa runs on-device, nothing this plan adds may send audio or
text off the machine (work-machine stance; say it in every module header).

## Task 2 — TTS: messages read aloud

- [ ] **A speak affordance on messages**: hover action + ⌘K row ("Read aloud") on any message
      in DM/channel/team-thread surfaces, calling the existing `speak_agent_message` path with
      the message's text. Playing state visible on the message row (the polish vocabulary's
      quiet plate); click again stops. One at a time — a second speak stops the first.
- [ ] **Auto-speak for the assistant**: a per-conversation toggle (DM header, three-dot menu)
      — "Speak replies" — off by default. When on, an incoming agent message in THAT
      conversation is spoken as it lands (whole message on arrival; streaming-TTS is not v1).
      The toggle is remembered per conversation (storage shape like diff-mode's flag).
- [ ] Model download UX: if voice models are absent, the first speak offers the existing
      `download_voice_models` flow (VoiceSettingsCard's own copy) rather than failing silently.
- [ ] Honesty: TTS state joins the message row, never the attention pipeline — a speaking app
      is not a "needs you" signal.
- [ ] Tests: unit for the queue/interrupt model; spec with the invoke mocked (speak called with
      the message text; toggle persists; second speak stops first).

## Task 3 — Dictation: konuşarak yazdırma

- [ ] **A mic button in the composer** (DM/channel/team-thread composers + the workspace's Ask
      box) and a chord (claimant-check first — the scratchMarkdownKeys.ts header's five-claimant
      discipline, AppKit ⌥-synthesis rule included; candidate: ⌃⌘D? check, do not assume).
      Press → `start_stt_pipeline` + mic capture (reuse the huddle's capture path — find it in
      Task 1; do NOT build a second `getUserMedia` wiring), partial transcripts stream into the
      composer as text (replacing the current partial, appending on final — the standard
      dictation UX), press again / Esc stops.
- [ ] **Visible capture state**: while the mic is open, an unmistakable indicator on the
      composer (recording dot + "listening…"), and the state auto-stops on send, on navigation
      away, and after N seconds of silence (read what the pipeline reports; if it has VAD,
      use its signal, do not invent a timer over one that exists).
- [ ] Dictation writes into the DRAFT only — never auto-sends. Send stays the owner's Enter.
- [ ] Language: check what sherpa model(s) the download ships — if multilingual or Turkish is
      available, expose the existing model choice (VoiceSettingsCard), do not hardcode English.
- [ ] Tests: unit for the partial/final fold into draft text; spec with the pipeline mocked
      (mic button toggles state, partials land in composer, Esc stops, send stops).

## Global Constraints

1000-line ratchet (lib.rs at 999 — new commands need the split first or registration via an
existing module's table); empty read is no answer; red proofs by the shasum discipline; gates
to real exit codes; **nothing here sends audio or text off the machine — local sherpa only**.

## Self-Review

**Riskiest:** the mic ownership. If the huddle's capture path assumes huddle state, reusing it
outside one may drag half the huddle machinery along. Task 1 exists to find that out before
Task 3 promises anything; if capture is inseparable, the honest fallback is webview
`getUserMedia` → `push_audio_pcm`, stated as a second wiring with the reason.

**Most likely to be got wrong quietly:** auto-speak turning into a nag. Off by default,
per-conversation, never global-on, and the first activation says how to turn it off.
