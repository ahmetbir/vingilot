# Deck (Phase 3) — Membership Syncs, Layout Does Not

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The original vision's Phase 3, honestly: Deck becomes the Workspace home where the owner **pins** what matters. The pin *set* is Workspace state, mutated through the coordinator's CAS protocol and therefore shared across devices; the pin *arrangement* is device-local and never syncs. A card pinned on another device arrives appended and visibly unplaced. A concurrent pin from a second device produces a real CAS conflict with an honest, non-destructive resolution — not a silent overwrite.

**Why now:** the cards finally have something to show (completed Runs, artifact commits, diffs). Just as important, this is the **first time the UI drives the CAS mutation protocol** — until now `apply_mutations` was only exercised by Rust tests. Deck is where ADR-002's central decision meets a human.

**Architecture:** Pin set lives in workspace state JSON under `deck.pins` and is written with `expected_revision`; a 409 surfaces the conflict UX instead of retrying blindly. Layout (order) lives in `localStorage`, keyed by workspace **and** a per-device id, so two devices genuinely differ. Unknown-to-this-device pin ids append at the end, rendered as "unplaced" until the owner moves them — the design's arriving-card affordance. All work in the island (`desktop/src/features/runs/**`) plus a tiny coordinator addition only if the mutation shape demands it.

**Tech Stack:** unchanged — island React + `node --test`; coordinator only if needed.

## Contracts fixed here

### Workspace state shape (written via the existing CAS endpoint)

```jsonc
{
  "deck": {
    "pins": [
      { "id": "<run-uuid>", "kind": "run",  "pinnedAt": "2026-08-04T10:00:00Z" }
      // future kinds (pr, surface) parse but need no UI here
    ]
  }
}
```

Mutation = `POST /v1/workspaces/{id}/mutations` with `expected_revision` and a merge-patch body carrying the whole `deck.pins` array (the array is the unit of change; per-element patching buys nothing at this size). A 409 returns the current revision and state hash — the UI reads the winner's pin set from a follow-up `GET` and renders the conflict.

### Island modules

```ts
// lib/deckPins.ts  (pure)
export type PinKind = "run";
export type Pin = { id: string; kind: PinKind; pinnedAt: string };
export const readPins: (state: unknown) => Pin[];              // tolerant: bad shapes → []
export const withPin: (pins: Pin[], p: Pin) => Pin[];          // idempotent by id
export const withoutPin: (pins: Pin[], id: string) => Pin[];
export const pinsDiff: (mine: Pin[], theirs: Pin[]) => { added: Pin[]; removed: Pin[] };  // for the conflict UX

// lib/deckLayout.ts  (device-local; localStorage)
export const deviceId: () => string;                            // created once, persisted
export const layoutKey: (workspaceId: string) => string;         // includes deviceId
export const readLayout: (workspaceId: string) => string[];      // ordered pin ids
export const writeLayout: (workspaceId: string, order: string[]) => void;
export const applyLayout: (pins: Pin[], order: string[]) => { placed: Pin[]; unplaced: Pin[] };
//   placed  = pins present in `order`, in that order
//   unplaced = pins absent from `order` (arrived from another device) — appended, flagged
export const moveInLayout: (order: string[], id: string, dir: -1 | 1) => string[];
```

### UI

- `DeckPane` gains a **PINNED** region above the existing lanes: cards in `placed` order, then `unplaced` cards rendered with a dashed border and the caption `pinned on another device — place it where you like`. Placing = pressing move (or the `Place` action), which inserts the id into the local order.
- Every Run card (lanes + `RunList` rows) gets a pin toggle (`data-testid="pin-<id>"`).
- Card content: objective, status chip, mode chip, and — when present — the artifact commit sha + `+N/−M` from the run's diff stat, so a pinned card shows the work, not just a name.
- A pinned id whose Run is missing from the API renders a **tombstone** card (`no longer available — unpin`), never a blank or a crash.
- Conflict banner (`data-testid="deck-conflict"`): `your pin didn't apply — <device/rev> changed the pinned set first`, listing added/removed via `pinsDiff`, with `Keep theirs` and `Re-apply mine on top` (the latter re-reads the current revision and issues a fresh CAS write — the retry names the revision it rebases onto, per ADR-002).
- Deck header carries `synced ·`/`as of` treatment already used elsewhere; while the control plane is unreachable, pin toggles disable with the inline reason (no fake queueing).
