# Executor V1 — Runs That Actually Run

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Run stops being an empty state machine: the executor claims a `ready` delegated Run, provisions a **real git worktree**, runs the Run's command under lease/fencing discipline, streams **evidence** rows the desktop Runs screen renders live, and drives the Run to `completed`/`failed` honestly. Proven by a full-loop integration test against real Postgres and a real (throwaway) git repository, plus screenshot evidence in the Buzz desktop UI.

**Architecture:** Evidence and leases become coordinator API surface (they exist in the DB/model already; leases lack HTTP). A new crate `vingilot-executor` joins the **existing** `vingilot/coordinator` Cargo workspace (ours — zero seams): a library `execute_run()` plus a thin `worker` poll loop. The executor talks to the coordinator **only through the HTTP API** (it is the control-plane contract; fencing via `validate-op` before every side-effecting operation). The desktop island gains an Evidence pane in `RunDetail` — island files only.

**Tech Stack:** Rust (tokio, reqwest for the executor's client, sqlx only inside coordinator), real `git` via `std::process::Command`, desktop island React + `node --test`.

- All new code in `vingilot/` or `desktop/src/features/runs/**` (island glob already declared). **No new touch-points expected**; if one becomes necessary, declare in seams.yaml + justify in the commit body.
- Gates per commit: `./vingilot/scripts/coordinator-check.sh` (with `COORD_DATABASE_URL=postgres://buzz:buzz_dev@localhost:5435/vingilot_coordinator`) and, when desktop files change, `cd desktop && pnpm check && pnpm typecheck && pnpm test`. `./vingilot/scripts/check-seams.sh` exit 0 always.
- No `unsafe`; no new `unwrap()`/`expect()` outside `#[cfg(test)]`. reqwest may be added to the executor crate ONLY (blocking feature off; rustls to avoid openssl).
- **The integration test is the deliverable's spine** — it must drive the WHOLE loop through public surfaces (HTTP + filesystem), not by poking the DB, except for assertions.
- Commands that may exceed ~120s: run via Bash `run_in_background` and poll the output file.
- Evidence is append-only and honest: the executor records what happened, including failures; a nonzero exit is a `failed` Run with the exit code in evidence, never a retry-until-green.

## Contracts fixed here

### Coordinator additions (Task 1)

```
POST /v1/bindings/{id}/lease           { ttl_secs }           → 200 { epoch, expires_at }
POST /v1/bindings/{id}/lease/renew     { epoch, ttl_secs }    → 200 { epoch, expires_at } | 409 stale epoch
POST /v1/runs/{id}/evidence            { kind, content }      → 201 { seq }
GET  /v1/runs/{id}/evidence?after=<seq> → 200 { evidence: [{seq, kind, content, created_at}] }
kind ∈ "command" | "output" | "error" | "note"   (content: text, ≤ 64 KiB per row)
```

New table (migration `0002_evidence.sql`):

```sql
CREATE TABLE run_evidence (
    run_id     UUID NOT NULL REFERENCES runs(id),
    seq        BIGINT NOT NULL,
    kind       TEXT NOT NULL CHECK (kind IN ('command','output','error','note')),
    content    TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (run_id, seq)
);
```

Also: add `http://127.0.0.1:4173` and `http://localhost:4173` to the CORS allowlist (the desktop screenshot harness origin — needed so visual evidence can show LIVE data; note it in the commit body).

### Executor (Tasks 2–3)

```rust
// vingilot/coordinator/executor/src/lib.rs
pub struct ExecutorConfig {
    pub coord_base: String,          // http://127.0.0.1:7117
    pub auth_token: String,
    pub repo_map: HashMap<String, PathBuf>,  // repo_id → local clone path (from VINGILOT_REPOS="buzz=/path,test=/path")
    pub worktree_root: PathBuf,      // where task worktrees are created
    pub command_template: Vec<String>, // argv; "{objective}" substituted. default: ["sh","-c","echo executing: {objective}"]
}
pub async fn execute_run(cfg: &ExecutorConfig, run_id: Uuid) -> Result<Outcome, ExecError>
pub enum Outcome { Completed, Failed { exit_code: i32 } }
```

`execute_run` sequence (each numbered step emits evidence; fencing = `validate-op` with the held epoch before EVERY side-effecting step after the lease exists):

1. GET run detail; require `status == "ready"`, `mode == "delegated"`, exactly one write-granted binding.
2. Transition `ready → running` (reason `"executor claimed"`).
3. Acquire lease on the binding → epoch.
4. `git worktree add <worktree_root>/<run_id> -b run/<run_id8>` in the mapped repo (validate-op first; evidence: the exact command + output).
5. Run the command (argv from template, cwd = the worktree; validate-op first). Stream stdout+stderr into `output`/`error` evidence rows (chunked ≤ 8 KiB), renew the lease every 30s while it runs.
6. Exit 0 → `running → verifying` (`"command exit 0"`) → `verifying → completed` (`"executor v1 auto-verify"`). Nonzero → `running → failed` (`"command exit <n>"`). Evidence `note` row with the outcome either way.
7. Worktree is **kept** (it is the task's artifact; retirement is UI work later).

`worker` bin subcommand: poll `GET /v1/workspaces/{id}/runs` every 3s, claim the oldest `ready` delegated run, `execute_run` it, repeat. One at a time — V1.
